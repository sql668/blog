这是本站的第一篇文章，顺手把它的发布流程记录清楚——因为以后每篇文章都走同一条路。

## 为什么是静态站点

博客的内容是文章，不是应用。静态站点没有数据库、没有运行时、没有需要维护的服务端进程，托管在 GitHub Pages 上零成本、零运维，而且构建产物就是一堆 HTML/CSS，任何托管都能接。

## 技术栈

- **Hugo**：单二进制、构建毫秒级、Markdown 直接出站。比起需要 Node 工具链的方案，它把"写作"和"构建"分得很干净。
- **PaperMod 主题**：默认排版干净，中文显示正常，支持暗色模式和目录。
- **GitHub Pages**：从仓库直接发布，免费。

## 发布流程

1. 新文章放在 `content/posts/` 下，Markdown 格式；
2. frontmatter 固定四个字段：`title`、`date`、`tags`、`author`；
3. 开一个分支提交，发 Pull Request；
4. **合并到 `main` 后由 GitHub Actions 自动构建并部署**。

也就是说，`main` 分支永远是线上状态，任何改动都要先过 PR。这条规则的用处不只是"防止手滑"：它让每次发布都留下一条可回滚、可讨论的记录，也让 AI 生成的草稿必须先经过一次人工确认才能上线。

## 接下来写什么

选题会从每天的技术热点里筛，标准是三条：技术深度够不够（有没有可展开的原理或数据）、读者会不会关心、以及和已有文章差不差得开。三样都过线才写。
